## 02 一句话总结

把已有 MAS 防护按"工具编排／共享记忆"两个面组织成 27 项确定性检查＋1 个四法官面板的级联（DEFER），在四个领域、300 个攻击变体上实测：规则先判可把攻击成功率从 34.6% 压到 6.1%（各域 1.3%–12.2%），63% 的被阻断尝试由确定性检查首先拦下，而"规则放行后全部再判一遍"不改变任何攻击结果——即判断只在攻击"不违反任何可陈述属性、仅误表意图"时才必要，且貌似合理的伪造记录能同时骗过规则与法官（[Paper: Abstract, PDF p. 1；§VI, §VII]）。

## 03 研究问题

- 具体问题：在一个同时运行访问控制、参数规则、有状态账本、记忆过滤与共识等多类控制的**多 Agent 管道**中，确定性检查究竟能独立结算多少验证工作，哪些攻击仍需 LLM 法官，不逐一判断会损失多少安全（RQ-1）；规则与法官各以什么方式失败、每条原则贡献什么、管道在合法工作阻断与时延上代价几何（RQ-2）；该模式是否跨领域、跨主模型、跨注入通道、跨法官面板、跨第三方攻击成立（RQ-3）（[Paper: §I, PDF p. 1–2]）。
- 研究意义：既有 MAS 防护"一次只针对一类攻击或一个通道"并被孤立评估，而部署中的 MAS 同时面对全部威胁；把最终裁决交给 LLM 法官"昂贵且难以审计"，"到底有多少裁决真的需要判断"是未测问题（[Paper: Abstract, §I]）。
- 现有方法不足：分层设计（LlamaFirewall、MCP-Guard、CASCADE）只在**单个 Agent 内部**组合检测器，没有跨工具调用、共享记忆与 Agent 间消息组合控制，也不报告此类管道有多少验证可在无判断下结算（[Paper: §I, §VIII]）；AgentTrust 把单 Agent 动作分为规则可决与仅法官可决两类，但多 Agent 管道（其规则还要读策略与状态）中的边界位置未被测量（[Paper: §I, §VIII]）。
- 核心问题：论文把自己定位为**度量**而非发明——"这些工作都在论证边界的某一边；我们度量它"（[Paper: §VIII]），并明确"我们不声称新的防护机制"（[Paper: §I]）。

## 04 研究背景与发展路径

> [Paper-framed; external verification not performed]

1. 历史类比与紧迫性：企业安全自动化正从确定性管道转向 LLM 驱动的 MAS；论文以注入漏洞主导 Web 漏洞榜十余年、默认口令使单个僵尸网络征用 60 万台 IoT 设备为例，论证"快速采纳而防护不足"的风险（[Paper: §I, PDF p. 1]）。
2. 协作结构自身引入攻击面：自主调用工具的 Agent 可被转化为"攻击者选定的动作"；支撑集体推理的共享记忆也能在 Agent 之间携带被污染或隐私内容；共谋行为可在无对抗影响下涌现。这些漏洞利用的是把 Agent 连到工具与共享状态的**集成架构**，与单个模型的鲁棒性无关；OAuth 2.1 等授权标准并非为自主长时会话设计（[Paper: §I]）。
3. 防护碎片化：注册表与身份绑定对抗工具假冒、特权与信息流控制对抗越权、共识与账本对抗单边动作、写入过滤对抗记忆污染、分层隔离对抗泄漏——每种防护通常只针对其对应攻击类设计与评估，忽略防护之间的交互（[Paper: §I]）。
4. 层叠化的例外及其局限：LlamaFirewall 报告分类器与推理审计器单独及组合的结果，MCP-Guard 与 CASCADE 从模式匹配升级到 LLM 判断，但都是单 Agent 内的检测器组合（[Paper: §I, §VIII]）。
5. 两极立场：一条线主张护栏不应依赖模型判断（符号护栏、policy-as-code、形式化验证护栏），另一条承认全设计式强制会牺牲 Agent 的灵活性（CaMeL、设计模式目录）；论文认为多数部署管道会落在两极之间，"在规则够用之处用规则，不够之处用模型"，而 Progent/FIDES/RTBAS/Datalog 引用监视器在工具边界强制特权与信息流（[Paper: §I, §VIII]）。
6. 本文位置：与 AgentTrust 边界"同形"，但补充"在有状态的多 Agent 工作流中，多数攻击必须破坏规则可检查的策略或状态，因此安全由规则承担"（[Paper: §VIII]）。

## 06 核心思想

1. 表层方法：把不受信内容的入口收敛为**两个集成面**（工具编排、记忆管理），把已有防护重述为**五条原则**（P1–P5），再按"最便宜最确定→最贵最不确定"排成 28 检查级联，只把规则未决的提案交给 3/4 法定人数的四法官面板，拒绝一律转人工（[Paper: §II-B, §III, Figure 1/4]）。
2. 核心洞见：判断需求不是全局属性，而是**工作流的属性**——"攻击的效果越能被策略或账本陈述出来，法官越不重要"；因此规则承担安全、法官的职责主要是**放行规则无法评估的合法工作**（CyberOps 里约 46 个百分点），而当攻击"停留在策略之内"（第三方基准的多数攻击如此）时，防御才由法官承担（[Paper: §VI-A, §VII-A]）。
3. `[Analysis]` 可迁移启示：对多 Agent 安全设计而言，这篇论文给出的不是"更强的护栏"，而是一套**边界审计方法**：先枚举内容入口（通道）、再为每个入口写"可陈述的属性"（清单、账本、证据一致性、密级），把无法陈述的属性（意图、合理性）留给判断，并单独度量判断的份额与代价。它同时给出两个反向警示：把攻击者可塑的上下文喂给比较类检查或法官会**降低**选择性；有状态防护若没有过期语义，会在真实运维节律中**自我否决**。

## 07 方法概览

- 输入：一个事件（告警/工单/请求）＋四阶段工作流＋该阶段的工具清单与参数规则＋共享向量库中的既有记录；攻击者内容经 C1–C5 之一注入（[Paper: §IV-A, Table I]）。
- 输出：执行／拒绝（拒绝即中止本阶段后续调用并进入人工复核队列）；评估侧输出 ASR、尝试率、阻断率、送判比例、合法拒绝率、完成率、中位时延、token（[Paper: §III-C, §V-D]）。
- 训练/外部工具：不训练任何模型。工具为独立 HTTP 服务器桩；存储为 ChromaDB 集合，用 Qwen3-Embedding-0.6B 嵌入；主模型为五个开源权重 LLM；面板为独立 LLM 端点，本地面板不外发事件内容（含 API 成员的面板 DIV4 会外发，论文明确这是部署需显式决定的数据出境问题）（[Paper: §IV-C, §II-C, Table XIV]）。
- 关键假设：主机编排器可信且未被攻陷（TCB）；验证器可信未失陷但不保证正确；攻击者不知防御规则、不自适应；工具为桩、记忆为合成；纵向拓扑提供完全仲裁所需的中介点（[Paper: §II-C, §IV-A, §VII-B]）。

```text
事件(C1) -> 阶段 Agent 提案(工具调用 / 记忆读写)
         -> P1 注册表与响应完整性 -> P2 清单/参数/输出分类
         -> 后果性调用进入 P3 确定性检查(上下文/意图链/账本/重放/同意/风险与自动门)
         -> 未决者(≈1/3) -> 四法官面板(3/4) -> allow 执行 / deny 人工复核
         写路径: P5 存储策略 -> P4 六项写入检查 -> commit
         读路径: P5 访问控制/查询范围 -> store -> 字段脱敏 -> 注入净化 -> deliver
         执行前重算哈希确认"批准的就是要执行的"；响应回程再查完整性
```

## 09 关键公式与符号

论文未提出新的数学模型；本节只登记原文给出的**可核查判据参数与符号**，以免为填充模板而虚构公式（[Paper: Table VIII, Appendix C, §VI-B]）。

- 记号（Appendix C）：阶段 $\phi$；提案 $\pi=\langle t, p\rangle$（工具 $t$、参数 $p$）；上下文 $\gamma$ 含事件证据 $e$；注册表 $R$；阶段清单 $M_\phi$；验证器集合 $V$ 与法定人数 $q$；嵌入 $E$ 与余弦 $\sigma$；存储 $s$、内容 $c$、元数据 $m$；$H$ 为 SHA-256。
- 目标—证据一致性（P2.2）：子串命中即放行，否则需 $\sigma \ge 0.5$；论文指出该检查**只能靠余弦阈值拒绝**（子串分支只会 allow），实测 468 次拒绝的得分全部落在 $0.30$–$0.50$ 之间。
- 敏感输出（P2.3）：$\sigma \ge 0.7$ 判定敏感类别后脱敏或拒绝。
- 自动批准门（P3.9）：离线门限为 $\text{scope}<0.2 \wedge \text{proportionality}>0.9$；在四域 4,397 个后果性提案上该门**一个都没有决定**。
- 法定人数：$q=3/4$（LOCAL4）；1/4、2/4、3/4、4/4 下的批准率分别为 82.8%、70.8%、54.4%、40.1%。
- 响应完整性（P1.2）：时延窗口 $0.01\,\text{ms} \le \Delta t \le 30\,\text{s}$；响应哈希在 5 个事件窗口内未见。
- 统计：分析单位为变体，每变体 3 次试验为重复测量；区间为按变体聚类的 95% cluster-bootstrap（10,000 重采样）；逐 AP 比较经 Holm 校正。

## 11 结论的正确解释

论文的主结论是一条**分界命题**，而非某个防护机制的有效性证明：

1. 在一条同时运行访问控制、参数规则、有状态账本、记忆过滤与共识的多 Agent 管道里，"必须违反可陈述属性"的攻击由确定性检查承担（四域合并 63.2% 的第一拦截者），把判断放在最后**不损失安全**（送判比例从 34.4% 升到 79.7% 不改变任何攻击结果）（C04/C05/C07）。
2. 判断的正当用途是**放行规则无法评估的合法工作**：在 CyberOps 买回约 46 个百分点合法工作、付出约 11 个百分点攻击成功率；域外代价差缩到 3.1 点（C06）。
3. 但当攻击停留在策略之内——第三方基准的多数攻击正是如此——防御才由法官承担：ASB 上确定性份额不足一半，TAMAS 上经工具起作用的三类攻击只有 10/202 次阻断由规则首先拦下（C07/C17）。
4. 两类失败各有其形：规则侧最典型的是**反选择**（风险打分门批准 84% 攻击、36% 合法）与**永不失效的状态**（87.5% 的合法后果性提案被拒）；法官侧最典型的是**给更多上下文反而批准更多攻击**、**同谱系面板弱 3.5 倍**、**跨域不迁移**（96.3% vs 36.8%）（C10/C13/C14/C16）。
5. 边界之外仍有一类攻击两边都挡不住：**错误但合理的伪造记录**（legal 伪造判例通过全部 P4 检查、法官在 8 次尝试写入中批准 5 次），作者把"工具返回内容的来源证明"列为剩余杠杆（C12）。

必须带上的边界限定：所有数字是在**静态攻击、工具桩、合成记忆、单一纵向骨架、主机可信、防御在 CyberOps 手工调定**的条件下取得的；作者明确"我们的数字是确定性层安全性的上界"，并声明"不声称新的防护机制"、"自建套件上的确定性份额部分循环"（C02/C17，[Paper: §I, §VII-B, §VI-C3]）。此外"200→56 个信任交互"只描述架构、**不可读作安全度量**（C03）。

## 14 学到的知识

### Agent-derived knowledge candidates

- 判断边界可被量化为三个可测口径：送判比例（judged fraction）、第一拦截者层级份额、"规则放行后全部再判"的 ASR 增量；三者共同把"要不要用 LLM 法官"从设计偏好变成实验问题（C04/C05/C07）。
- 攻击面收敛的经验规律：把 35 个向量按入口归类后，除模型内部攻击外只剩工具编排与记忆管理两个面；Agent 间消息在主机中介架构下沿编排路径传递，因此不是第三个面，但需要单独通道（C01）。
- 规则承担多少防御是**工作流的属性**，不是管道的普适常数：攻击效果越能被策略或账本陈述出来，法官越不重要；在 ASB/TAMAS 上确定性份额不足一半（C07/C17）。
- 按"上下文打分"批准低风险动作是反选择的，因为分数由攻击者可塑的证据算出；正确做法是按动作类别批准（C10）。
- 比较类检查（把提案目标与事件证据比对）若把攻击者可控文本当作"证据"，就构成可被满足性规避的绕过；限制为结构化字段可同时提升攻击拦截（199→290）并降低误伤（51→47）（C11）。
- 有状态防护必须有失效语义：骨架键＋1 事件窗口可把合法拒绝从 87.5% 降到 5–24%，过期比身份键更能恢复可用性（C16）。
- LLM 面板需要模型谱系多样性：同一批决策上，单法官放行 36、同谱系三法官放行 127、三谱系三法官放行 18，而良性拒绝率几乎不变（C15）。
- 法官输入越"丰富"不等于越好：把规则所读字段（含攻击者可写文本）交给法官，反而使其批准更多攻击（30%→54%）（C14）。
- 判断跨域不迁移：面板在调优域批准 96.3% 合法提案，在未调优域低至 36.8%（C13）。
- "错误但合理"的记录是规则与法官的共同盲区；来源证明（provenance）是剩余杠杆（C12）。
- 仅连接性访问控制对注入无效：ASB 上 ACL 拦住的注入动作为 0，因为注入动作使用 Agent 本就有权调用的工具（C17）。
- 防护的代价必须与安全同表报告：同一套规则在四域给出 1.3%–12.2% 的 ASR，却给出 7.8%–28.0% 的合法拒绝率——"安全保持、代价不保持"（C18/C19）。

## 16 研究想法

### Agent-derived research candidates

#### 候选想法 1：把"证据"与"叙述"分离的比较类检查

- 起点：C11 显示 P2.2 的目标—证据检查可被"把目标写进告警字段"满足性规避，而把证据限制为结构化字段后攻击拒绝从 199 升到 290、兄弟攻击调用拦下 122/149、合法拒绝从 51 降到 47。
- `[Hypothesis]` 核心假设：任何"提案目标须出现在事件证据中"的比较类检查，其绕过面恰等于证据中**攻击者可写**的字段集合；把比较域严格限定为带来源标记的结构化字段，可在不损失选择性的前提下消除该绕过面。
- 相对本文的变化：本文只做了一次离线重放（换 P2.2 的证据域），未把"字段来源标记"上升为通用机制，也未测攻击者转而伪造结构化字段的情形。
- 初步方法：为每个事件字段附加写入者与可信等级标签，比较类检查只接受指定可信等级的字段；对不可信字段改为"仅可用于提示、不可用于授权"。
- 验证方案：在同一 24 组父/兄弟变体上加装"伪造结构化字段"的第三代变体，比较三种证据域（全字段／仅结构化／仅带来源标记的结构化）的 ASR 与合法拒绝率，按变体配对报告区间。
- 证伪条件：若攻击者可通过伪造结构化字段使第三代变体的成功率回到父变体水平（约 90%），或合法拒绝率显著上升，则假设不成立。
- 可能失败原因：真实系统中大量合法证据本身就是自由文本（工单描述、告警摘要），限制证据域会把误伤推高；来源标记本身依赖 TCB 中的主机中介。
- 创新状态：unverified，需检索现有技术（信息流标签、引用监视器、structured-output provenance）。

#### 候选想法 2：状态失效语义作为一等安全属性

- 起点：C16 显示永不失效的重放键与账本在持久状态下把良性完成率从 97% 压到 5%，而窗口过期与身份键化可降到 5–24%；作者明确"攻击诱导的状态是否退化部署仍未测"。
- `[Hypothesis]` 核心假设：把状态失效策略（窗口长度、键粒度、过期依据）作为显式安全属性建模，可找到一组使"残余攻击成功率"与"合法拒绝率"同时不劣化的配置；反之，任何只按可用性调优的过期策略都会被跨事件累积攻击利用。
- 相对本文的变化：本文只报告了可用性侧的过期收益，未测攻击侧的代价，也未把两者放在同一帕累托前沿上。
- 初步方法：在持久状态下重跑 AP-6（重放与跨事件累积）与 AP-12（并发/拆分绕过），对窗口 1/2/5/∞ 与两种键（骨架键、身份键）做全交叉，报告 ASR—合法拒绝二维前沿。
- 证伪条件：若存在某窗口使合法拒绝下降但 AP-6/AP-12 的 ASR 回到 FLAT 水平，则"失效策略可同时保持安全"不成立。
- 可能失败原因：真实运维节律（同类事件天然成批出现）与攻击的跨事件累积在特征上不可分；长时任务需要保留状态。
- 创新状态：unverified，需检索现有技术（rate-limiting、idempotency keys、capability expiry）。

#### 候选想法 3：谱系多样性与输入净化作为面板的两个独立旋钮

- 起点：C13/C14/C15——同谱系三法官比单法官弱 3.5 倍（127 vs 36 放行），而把攻击者可写文本从法官输入中移除后 Gemma 的攻击批准率从 54% 回到 30%；两个效应方向一致但机制不同。
- `[Hypothesis]` 核心假设：面板的漏放率可被分解为"相关性失败"（同谱系共享盲区）与"说服失败"（输入含攻击者文本）两个独立因子，分别由谱系多样性与输入净化控制；同时优化两者才能逼近 NOJUDGE 的安全水平而不付其代价。
- 相对本文的变化：本文分别测了两个因子（面板对照、输入对照），但从未做 2×2 交叉，也未在自建套件上测净化后的面板。
- 初步方法：构造 {单谱系, 多谱系} × {原始输入, 净化输入} 四组面板，在同一批记录决策上重放，并在自建 T2 路径（AP-9/AP-10）上 live 复验。
- 证伪条件：若两因子交互显著（净化只在多谱系下有效，或反之），则"两个独立旋钮"的分解不成立。
- 可能失败原因：净化本身可能删除判断所需的合法线索（作者已指出净化文本"不能可靠区分合法运维指令与攻击指令"）。
- 创新状态：unverified，需检索现有技术（LLM-as-a-judge 鲁棒性、prompt injection 对抗 LLM 评审、ensemble diversity）。
