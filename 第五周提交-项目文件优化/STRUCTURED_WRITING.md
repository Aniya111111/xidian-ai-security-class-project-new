# 有证据约束的综述整稿准入

Obsidian Evidence-Grounded Ideation 默认采用结构化流程。修改代码后需重启01；04不需要更换模式。

流程：读取已选论文的本地PDF → 保存原文摘录、文件SHA-256和PDF文件页码 → 按证据编号生成单条主张 → 独立模型调用逐条核验主张及条件 → 排除未获支持的条目 → 由程序组装正文与引用，不再自由改写已核验事实。

每次最多三轮修复。部分支持、证据不足、冲突、引文或数字不匹配、来源覆盖不足都不能获得准入。通过至少需要每个选中来源两条有原文依据的主张，且覆盖效果与边界。未通过时保存失败原因，不自动标记作者认可。

生成的主要文件：

- `report.md`：有主张编号和证据编号的综述材料。
- `selected_evidence.md`：实际使用的PDF摘录；不是整篇全文。
- `primary_provenance.json`：本地PDF路径、哈希、文件页码、摘录及摘录哈希。
- `structured_review.json`：每轮候选、排除原因和逐条核验结果。
- `draft_readiness.json`：是否可进入综述草稿起草及其范围。
- `verified_claims.json`：有核验者、理由、范围和快照哈希的主张清单。机器核验不会伪装成人工认可。
- `chapter_input.md`：通过准入后导出的整稿输入，证据和来源去重，遵守36000字符预算。
- `manuscript_plan.json`：对应主张、输入大小、后续逐段核验要求。

`ready_for_drafting=true` 仅表示可起草有来源边界的文献综述。它不表示作者已经认可、不表示全文每页都被人工核验，也不提供原创研究论文所需的新方法或实验。生成整稿后仍需逐段核验。

读取已经通过的材料时，会再次核对报告、主张清单、审核附件及实际PDF哈希；PDF更新、证据或报告变化后，旧准入无效。缓存签名也包括实际PDF哈希。

缺少本地PDF、PDF只有图片无法提取、输入超预算或模型核验不收敛时，流程停止授予准入。应补原文、OCR或按来源/章节拆分，不截断证据后假装通过。

开发排查可显式设置 `OBSIDIAN_STRUCTURED_WRITING=false` 使用历史自由综合流程。历史流程不生成本协议的准入附件，不能把格式检查通过当成整稿准入。
