### 一、 已有文献的主要研究问题与结论综合

**1. 核心研究问题**
现有文献共同指向的核心问题是：**在层级式或多向交互的 Multi-Agent 系统中，单层 Agent 的局部安全保证能否直接组合（Compose）为整个系统的宏观安全？** 具体分解为三个维度：
*   **协议层**：跨越 Agent 边界时，信息是否被隐式地提升了信任级别？[Paper: Section VI-A 末段; Section VII]
*   **评估层**：如何在不重建整套基础设施的前提下，对被攻陷 Agent 的攻击成功率进行受控、可复用的测量？[Paper: PDF p. 2–3, Section 1；PDF p. 10, Section 6]
*   **博弈层**：在多 Agent 辩论（Debate）或协作场景中，对抗性攻击是被吸收还是被放大？共谋模式下的漏洞有何特征？[Paper: PDF p. 2 §1, p. 7 RQ1/RQ2]

**2. 关键结论与经验发现**
*   **[Paper: Can CaMeLs Talk?] (CaMeL系)**：
    *   （原论文结论）**逐 Agent 部署 CaMeL 不等于系统安全。** 单个 Agent 满足控制流完整性（CFI），但在层级调用中会发生“边界洗白（Boundary Whitewashing）”现象：父 Agent 把工具返回的不可信值写入子 Agent 的自然语言指令参数中，子 Agent 将父 Agent 视作用户，导致该不可信数据以“可信输入”身份进入子 Agent 大模型改写其控制流。[Paper: Abstract; Section I 末段; Section III-A; Section III-C]
    *   （原论文结论）修复方案是将通信通道显式双通道化并做运行时强制：分离 `message`（绝对可信指令）与 `variables`（携带 capabilities 与来源证明的可疑数据）。在此架构下，只要存在返回值不可信的工具，即使不使用任何安全策略，解释器也必须递归展开系统级控制流以防止 CFI 被违反。[Paper: Section IV-A; Section IV-B; Section IV-C]
*   **[Paper: ORBIT] (评估框架)**：
    *   （原论文结论）作者通过实证指出一个经验发现：能够将被攻陷 Agent 的攻击成功率降低 60 个百分点的“逐动作防御（per-action defense）”，对任何形式的“共谋（collusion）”都**完全没有可测的保护作用**。这种脆弱性仅存在于各自良性动作的组合之中。[Paper: PDF p. 8–9, Section 5 (1)]
    *   （原论文结论）不同的安全机制代价各异。例如在 BrowserART 场景上，“系统提示词（system prompt）隔离”表现较强；而在 OS-Harm 跨场景对照中，某些攻击的影响被放大了近 3.8 倍。[Paper: PDF p. 34, Table 10 caption；PDF p. 38, Table 18 caption]
*   **[Paper: MADBench] (辩论基准)**：
    *   （原论文结论）目前尚不存在从分层视角系统分析 Multi-Agent Debate 安全性的基准。现有的工作要么假设全员诚实，要么只关注单点攻击。[Paper: PDF p. 1–2 §1, p. 2 §1]

**3. 各研究间的联系、分歧及适用边界**
*   **拓扑与交互模式的差异**：
    *   CaMeL系主要聚焦于**严格的有向树状层级拓扑**（Agent-as-tool 委派模式）；而 MADBench 针对的是**辩论图结构**（可能包含循环、点对点通信与动态路由）。两者的结论不可直接移植，因为“传递控制权给子任务”与“交换观点”产生的攻击传播路径截然不同。[Paper: Section III-A (CaMeL); PDF p. 1 §1 (MADBench)]
*   **威胁模型的局限性与侧重**：
    *   CaMeL 的原生威胁模型仅覆盖外部攻击者通过外部数据源注入的情况，且实验中所有 Agent 本体均诚实运行。其未能覆盖恶意成员、共谋或拜占庭容错场景。[Paper: Section III-A（攻击者设定）]
    *   ORBIT 的框架本身支持配置多种攻击类型与记忆可见性（如共享工作空间 `shared_cot`），但其默认的多项实验仅在较低的共享内存设置下运行，缺乏对“共享记忆污染”作为独立攻击面的系统性扫掠。[Paper: PDF p. 33, Appendix I, Table 9]
*   **结论验证强度的分歧**：
    *   CaMeL 报告在某些设定下的攻击成功率为 0.0%，但这在小样本（n=949）下 Wilson 置信区间的 95% 上界约为 0.4%，且未针对自适应攻击进行测试，无法等同于“彻底解决”。[Paper: Analysis 部分观察]
    *   ORBIT 在不同测试单元格中混用了不同版本的 LLM Judge（如 GPT-4o 与 GPT-4.1）来判定有害性，这可能导致跨条件比较时的判决漂移，从而模糊了真实的安全收益。[Paper: PDF p. 34, Table 10 caption (Analysis 部分观察)]

### 二、 证据包支持的研究空白与候选写作方向

综合三份审查过的卡片，当前文献存在以下未被完全解决的系统性空白（Evidence-supported Research Gaps）：

1.  **安全机制的交叉失效（Cross-Failure Blind Spots）**：
    *   CaMeL 证明了“无策略保护下的边界洗白”是必然发生的，但其所用实验策略为 $S=\emptyset$（平凡策略），因此无法推断在开启权限控制（Capability Control）后，基于变量的访问是否会阻断特定越权行为。
    *   ORBIT 证明了防御对共谋无效，但未深入探讨在 CAmeL 式的“接口隔离”架构下，共谋或横向移动（Lateral Movement）是否会被限制在更小的连通分量内。**（候选方向：测试协议层边界隔离与全局行为监控在应对混合攻击时的互补性）**
2.  **复杂依赖链路下的间接推理污染**：
    *   CaMeL 承认当前的解释器实现可能漏检隐式依赖（例如若 `flag` 源自工具输出，但赋值语句被包装在其他分支中，解释器可能仍将其标记为可信）。
    *   ORBIT 指出摘要型净化机制（Dual-LLM）往往同时剥离了注入指令和有效任务语义，造成了“净化与信息损失同源”的上限瓶颈。**（候选方向：设计一种既能剥离上下文无关噪声，又能保留结构化任务参数的中间态传递协议）**
3.  **评估指标的机器自洽性偏差**：
    *   现有多数工作依赖正则表达式匹配或 LLM Judge 来判定攻击成功，两者之间存在逻辑不一致（例如成功触发了工具但 Judge 判分为无害）。且 Judge 本身的性能波动会掩盖底层代理防御的真实效力。**（候选方向：提出一种去中心化的多裁判共识机制，或定义不依赖黑盒 Judge 的确定性状态校验指标）**

### 三、 研究设想（Hypotheses）与待验证命题

*(注：以下为根据文献空白提炼的本次规划建议，并非已验证事实)*

*   **H1（边界穿透假设）**：在层级式调度中，如果不对 `get_variable` 获取的值施加静态数据流分析约束（即允许变量参与自然语言指令的拼接），无论子 Agent 自身的 CFI 检测多么严密，都会出现系统级的控制流重定向（System-level CFI Violation）。
*   **H2（协同防御增益假设）**：单独使用的逐动作防御在遭遇目标明确的共谋攻击时会全面失守；但如果结合类似 CaMeL 的“显式可信消息通道隔离”，由于共谋方必须通过 `variables` 通道沟通，其发出的任何非预期数据都将失去触发下游 Agent 执行权限的能力。
*   **H3（评测方差假设）**：在未严格控制模型版本与随机种子、并使用异构 Judge 的情况下，关于“某类防御优于另一类防御”的经验排名统计功效极低，无法支撑工程部署决策。

### 四、 最小系统设计与实现计划（Minimal System Plan）

本阶段不进行代码编写或环境启动，仅规划用于后续复现与写作的对比基准。

| 设计要素 | 基线方案 (Baseline / Unprotected) | 保护变体 (Protected Variant) | 设计依据与来源关联 |
| :--- | :--- | :--- | :--- |
| **基础架构** | 标准的主从多 Agent 架构（如 LangGraph 或 AutoGen 默认路由）。根节点接收用户指令，依次转发给专门子 Agent。 | 在父子节点通信处引入**双通道抽象层**。`message` 通道仅传输不可变的 Prompt；`data` 通道传输带 Provenance 标签的结构化对象。 | 借鉴 CaMeL 的边界洗白修复思路与 ORBIT 的可配置拓扑特性。[Paper: Section IV-A; ORBIT Sec 3.2 Layer 1-4] |
| **信任边界** | 认为父 Agent 传递给子 Agent 的任何文本都是可信的系统指令。 | 只有由父 Agent 生成的固定 Prompt 模板视为可信；来自数据库、Web 检索等工具的返回值在未经显式转义前一律视为“有毒/受限”。 | 基于 CaMeL 的核心论点：“跨越 Agent 边界不应隐式提升信息的信任级别”。[Paper: Section VI-A] |
| **任务设定** | 简单工具调用链：解析 SQL 查询结果 -> 发送电子邮件。 | 同上。但在任务描述中植入隐蔽的条件跳转要求（如：“如果查询金额大于 X，则额外触发转账”）。 | 用于探测攻击者是否可以利用“分支引导（Branch steering）”绕过意图识别。[Paper: Section IV-C (Analysis 部分观察); ORBIT Sec 3.2 Attack] |
| **对抗测试集** | 使用公开的提示注入样例集合（如 OWASP Top 10 LLM variants），并在其中构造需经过两跳路由才能生效的长尾注入指令。 | 同左。 | 填补 ORBIT 提到的测试覆盖度不足及 CaMeL 仅测单一短注入的问题。[Paper: ORBIT Analysis; CaMeL Table III] |
| **度量指标** | 1. ASR (Attack Success Rate)<br>2. Action Precision (精准完成合法动作的比例)<br>3. False Positive Rate (误杀率) | 同左。增加一项：Control Flow Drift (控制流偏离度)，即实际执行的工具序列与根节点预期序列的编辑距离。 | ASR 和 效用下降 是评估防御成本的标准。[Paper: ORBIT PDF p. 6 Sec 3.4; CaMeL Table V] |

### 六、 局限性说明与证伪条件

本研究与上述文献综述同样面临以下已知或潜在限制：
1.  **能力评估的非单调性风险**：不同规模的后端模型（Small vs Large PLLM）在面对同一套协议改造时表现出巨大的鲁棒性差异。CaMeL 笔记提示“能力越强代价越小”的观点并未得到回归分析的定量支持，可能存在模型特定的过拟合或幻觉抗性。[Paper: Analysis (CaMeL)]
2.  **复杂推理任务的适配性**：简单的命令式任务可以通过硬编码的 schema 处理，但对于开放域、需要长时间跨轮次规划的任务，极度收紧的信任通道（仅传 message）可能会导致严重的可用性崩溃，使得安全性与功能性陷入零和博弈。
3.  **实时性与计算开销**：显式的依赖追踪与双向通道的建立会增加单次调用的延迟。在大规模并发请求（如每秒数百次工具调用）下，纯解释器层面的运行时检查可能会成为系统瓶颈。[Paper: ORBIT Analysis (Judge latency limit)]
4.  **证伪条件**：如果在严格的自适应红队攻击（Adaptive Red-teaming）中，开启了显式双通道隔离的多 Agent 系统，其 ASR 仍然显著高于单 Agent 的本地防御上限（即突破了对比组的置信区间下限），则说明基于接口隔离的控制流防御在通用场景下是不充分的，可能需要转向基于形式化验证的全局图剪枝技术。
