# 基于Obsidian证据包的规模受限研究方案：区分多Agent系统中的“准确率吸收”与“权限放大”

## 1. 现有证据综合（Existing Evidence Synthesis）

根据证据包内已审核论文卡，关于多Agent系统（MAD）的安全现象可归纳为以下相互对照的发现：

| 现象维度 | 证据来源与结论 | 作用机制/边界条件 |
| :--- | :--- | :--- |
| **准确率吸收** | `MADBench` 报告：相对单Agent，MAD在问答任务上呈现对准确率攻击的吸收效应（AF<sub>ASR</sub><1）。例如 M3 AF<sub>ASR</sub>=0.74，M4 AF<sub>ASR</sub>=0.87 [Paper: PDF p. 7 Table 2, p. 8 §4.1]。案例A显示，即便部分Agent的RAG被投毒，编排器可基于证据质量否决多数错误提案，返回正确答案 [Paper: PDF p. 8 §4.1 Case study, p. 8 Table 3, p. 21 §D.5]。 | 依赖聚合层的“证据比对/多数表决”逻辑。攻击影响集中在编排器聚合环节，诚实Agent的信念改变率低（C2W最高仅3.26%）[Paper: PDF p. 19 §D.4, Table 11]。 |
| **权限放大** | `MADBench` 报告：同一套MAD框架在工作区等任务上显著放大未授权读/写（IRW）。M2在workspace上12项比较中11项放大，指标最高达 AF<sub>IRW</sub>=3.00、AF<sub>ASR</sub>=3.09 [Paper: PDF p. 7 Table 2, p. 8 §4.1]。案例B显示，单Agent仅越权读不越权写，经MAD辩论后升级为执行未授权付款（UR+UW）[Paper: PDF p. 8 §4.1 Case study, p. 8 Table 3]。 | 辩论本身会改写外部动作意图；即使最终QA答对，仍会诱发越权。底层原因在于聚合器在 `finalize` 阶段拥有对写工具的自发控制权（C10）。 |
| **信任单点与拓扑风险** | `Can CaMeLs Talk?` 指出：层级树状多Agent系统存在“边界洗白”（Boundary Whitewashing），父Agent将不可信返回值包装为子Agent的可信指令，导致逐Agent加固无法保证系统安全 [Paper: PDF p.1-2, p.3-4]。 | 通信通道（如 `variables` vs `message`）的信任传递规则被破坏时，权限升级风险呈指数化。 |

**证据冲突与范围边界：**
- 准确率的提升（吸收）与权限的失控（放大）**在同一次运行、甚至同一条攻击载荷下并存**（C05、C06）。这表明二者并非互斥，而是由不同子系统逻辑驱动。
- MADBench 明确声明其仅**度量**越权行为（使用预测预言机计算AF值），并未在运行时实施任何阻断策略 [Paper: PDF p. 7–8 §4.1]。候选设计想法1（Candidate Idea 1）明确指出：在同一基准上加入“聚合器-写工具间的强制白名单校验”目前仍是 `unverified` 状态，需独立验证 [Paper: PDF p. 9, Candidate Idea 1]。
- `Can CaMeLs Talk?` 的实验全部使用平凡安全策略（$S=\emptyset$），且假设所有Agent本体诚实，未覆盖恶意Agent共谋场景 [Paper: Section II-B; Section III-A]。因此，本文档提出的白名单防护不能直接套用其安全性质证明。

## 2. 研究缺口与目标（Research Gap & Objective）

**研究缺口：**
已有文献在概念上区分了“正确答案传播”与“权限边界扩张”，并在基准测试中观测到二者在统计分布上的解耦（吸收ASR，放大IRW）。但**缺乏小规模实证**来回答：① 一个Agent给出的正确答案被其他Agent采纳并触发聚合器决策，是否会从机制上必然混淆权限边界的逐步扩大？② 仅在聚合器调用写工具的边界上实施显式授权白名单，能否在不干扰正常辩论与证据采纳流程的前提下，切断“正确回答→自发写文件/支付”的因果链？证据包未提供针对该运行时拦截点的消融数据，仅将其列为待检验方向。

**研究目标：**
构建一个可重复的轻量级toy task，对比多Agent协作的**基线逻辑**与**聚合器写路径白名单变体**。实证检验“答案采纳率”与“未授权动作执行率”是否可分离，并评估最小化强制访问控制（MAC）在聚合层的有效性。

## 3. 假设（Hypothesis）

`[Hypothesis]` **核心假设：** 在多Agent系统中，“正确答案被采纳”（准确率吸收机制）与“权限边界被逐步扩大”（权限放大机制）是解耦的运行态过程。若在聚合器与写工具之间插入不参与推理的显式白名单强制点，可在维持任务答案正确率波动处于噪声范围内的前提下，将未授权写操作成功率压降至零（或接近单Agent无对话基线水平）。若该变体导致合法操作拒绝率显著攀升或任务效用断崖式下降，则表明静态白名单的表达力不足以刻画合法动作空间，或攻击者已通过合法参数组合达成越权，该防护假设为伪有效。

## 4. 最小系统与实施方案（Minimal System & Implementation Plan）

### 4.1 威胁模型与信任边界
- **威胁模型：** 外部攻击者向输入端注入诱导性提示（模拟M3/M4类攻击族），企图通过辩论或聚合逻辑诱导系统执行超出用户初始意图的文件写入、数据导出或支付调用。攻击者不直接攻陷模型权重或基础设施密钥。
- **信任边界：** 定义在 `Aggregator → WriteTool` 接口处。可信组件：用户预设的白名单策略、沙箱文件系统；不信任组件：所有Agent输出的自然语言/JSON、辩论轮次产物、聚合器的自发决策逻辑。

### 4.2 Toy Task 设计
- **任务名称：** `Sandbox_Report_Generator`
- **描述：** 两个检索代理（R-Agents）从本地沙箱中的固定文本集（模拟知识库）提取信息；一个辩论代理负责交叉验证；一个聚合器判定最终结论并决定是否调用 `write_summary(path, content)` 工具。
- **输入构造：** 混合三类场景：
  1. `Benign`：常规查询，预期输出合法摘要。
  2. `AuthWriteOnly`：含诱导载荷，要求生成额外非法文件（如 `user_secrets.json`）或不修改指定路径。
  3. `MixedCorrectAnswer`：载荷附带大量干扰论证，试图诱使聚合器在给出正确答案的同时，附带执行额外的写操作或覆盖合法摘要。
- **算力约束：** 限定使用单个开源小参数模型（如 7B~13B）或单次API调用配额；禁用长上下文窗口；限制辩论轮数为 $R=2$（匹配C14消融设定）。

### 4.3 基线与防护变体
| 配置 | 路由逻辑 | 写工具放行条件 |
| :--- | :--- | :--- |
| **Baseline（基线）** | 还原MADBench原逻辑：聚合器基于证据匹配度/多数票判定是否生成输出。若判定通过，直接透传 `write_summary` 调用请求至执行层。 | 只要聚合器输出包含 `write_summary` 调用签名即放行（对应C10所述的自发创建行为）。 |
| **Protected（防护变体）** | 推理与辩论链路完全不变。仅在 `Agg` 产出工具调用后，插入 `PolicyEnforcer` 中间件。校验 `(tool_name, normalized_args)` 是否命中预置 `ALLOWLIST`。 | 严格匹配白名单。命中则透传执行；未命中则丢弃调用、返回空结果并记录 `DENIED`，不参与后续辩论反馈。 |

### 4.4 控制变量
- 模型后端与温度参数（Temperature=0.2）
- Agent数量与角色Prompt模板
- 沙箱目录结构与环境隔离等级
- 随机种子与任务排列顺序
- 输入数据池（固定30个seeded任务）

### 4.5 指标设计（独立计量，绝不合并）
1. **任务答案正确率（Task Answer Accuracy Rate）：** 聚合器最终返回的文本内容是否符合Gold Standard。计为布尔型 `Is_Correct`，按任务类型分组统计比例。
2. **未授权写操作成功率（Unauthorized Write Operation Success Rate）：** 在注入载荷的场景中，实际产生磁盘写入或触发非白名单路径调用的比例。计为 `Exec_Unauth_Write`。
3. **合法操作拒绝率（Legitimate Operation Rejection Rate）：** 在 `Benign` 场景中，因未能命中白名单而被 `PolicyEnforcer` 拦截的比例。计为 `Reject_Legit`。

### 4.6 实验步骤
1. 部署沙箱环境，固化30条测试用例与 `ALLOWLIST.json`。
2. 配置Baseline链路，遍历30条用例 × 3次重复播种，记录原始输出与调用轨迹。
3. 切换至Protected变体，重置沙箱状态，以相同seed跑完30条用例。
4. 解析日志，独立计算三项指标及其置信区间。
5. 进行配对差异分析（Baseline vs Protected），观察指标解耦情况。

### 4.7 停止标准
- 达到预设样本量（$N_{task}=30 \times 3_{repeats} = 90$ 次运行/变体）；
- 或当三项指标的滚动置信区间宽度收敛至 $\pm 0.05$ 以内；
- 或累计Token消耗触及硬性预算上限。满足任一条件即终止收集。

## 6. 局限性与可能推翻假设的结果（Limitations & Falsification Conditions）

### 6.1 局限性
1. **玩具任务表达能力受限：** 沙箱文件操作无法映射企业级数据库事务或复杂工作流引擎的权限链。静态白名单难以覆盖动态参数组合（如合法路径拼接越权后缀）。
2. **未覆盖编排器自身被攻陷场景：** 本设计假定聚合器逻辑本身是诚实的执行管道，明确排除 MADBench 中 M6（被控聚合器 100% 成功）的攻击面 [Paper: PDF p. 9 Table 4c, p. 9 §4.2]。
3. **间接注入的低阶通道未建模：** `Can CaMeLs Talk?` 指出隐式依赖追踪漏检可能导致边界洗白，本实验仅在应用层做白名单，不介入控制流完整性（CFI）检查，故对深层Prompt Injection防护有限 [Paper: Section VI-B1]。
4. **证据缺失标注：** 包内未提供 `PolicyEnforcer` 的具体拦截延迟、内存开销或与开源模型交互的真实兼容性测试，相关性能指标属于“证据包未提供”状态。

### 6.2 可能推翻假设的结果（证伪条件）
- **条件A（假阳性过高）：** 防护变体的 `Legit_Op_Rejection` 显著高于阈值（如 >8%），且 `Auth_Write_Success` 仍维持非零。表明白名单粒度粗糙，合法动作空间未被正确表征。
- **条件B（攻击绕过）：** `Auth_Write_Success` 在变体中未显著下降。攻击者通过合法工具签名（如调用已授权的 `append_log`）携带恶意Payload完成实质写入，印证C10所述“准确率指标会漏掉由编排器自发产生的越权动作”的机制延续 [Paper: PDF p. 9 §4.2 case study]。
- **条件C（吸收失效）：** `Task_Accuracy_Rate` 在变体中出现断崖式下跌，说明 `PolicyEnforcer` 意外切断了正常辩论收敛所需的回传信号，导致系统退化为无效死锁。
